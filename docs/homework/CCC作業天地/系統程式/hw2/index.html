直譯器（Interpreter）

直譯器不走「編譯」這條路，而是拿到程式碼後立刻執行。想像成一個即時口譯員——你說一句，他翻一句，馬上行動。

執行流程與 Level 對照

1
Tokenizer（斷詞）
把程式碼字串拆成一個個 Token。每個 Token 有類型（數字、運算子、關鍵字）和值。
L3 — Tokenizer：將字元序列切分為 Token 流
"1 + 2 * 3" → [NUM:1, PLUS, NUM:2, MUL, NUM:3]
↓
2
AST（語法樹）
將 Token 組裝成樹狀結構，表現運算的優先順序。乘法的層級高於加法，所以在樹的上層。
L4 — AST：遞迴下降解析，將 Token 流組裝為語法樹
1 + (2 * 3) →
　　　＋
　　／　＼
　１　　　＊
　　　　／　＼
　　　　２　　３
↓
3
Eval（執行）
從樹根開始，遞迴走訪每個節點，執行運算。遇見數字就回傳，遇見運算子就對左右子樹先求值再計算。
L2 — 文字替換：不做Tokenizer，直接用字串判斷做計算（示範用）
L5 — 完整直譯器：串連 L3 Tokenizer + L4 AST + Eval，真正可用

Level 递进邏輯

L1
什麼是電腦——用最原始的方式理解記憶體與指令。不涉及任何高階概念。
L2
直譯器基礎——模仿計算機的思維，用 if/switch 做字串判斷，不依賴Tokenizer，純文字替換。
L3
Tokenizer——為什麼需要？L2 的缺點：無法處理空白、無法擴展支援多運算子。Tokenizer 把問題正規化。
L4
AST——為什麼需要？Tokenizer 只告訴你「有哪些Token」，但不知道「誰先算」。AST 建立優先順序結構。
L5
完整直譯器——串連 L2~L4 的成果。Tokenizer + AST + Eval，三者協作形成真正的解譯器。
⭐ 關鍵：直譯器沒有「寫入檔案」這步

原始碼 → 直譯器 → 直接輸出結果。沒有中間產物，執行完就結束。

編譯器（Compiler）

編譯器不走即時翻譯，而是先把原始碼翻譯成一種中介語言（Bytecode），再由虛擬機器（VM）執行。想像成翻譯書——先把整本譯好，讀者什麼時候想看都可以。

執行流程與 Level 對照

1
Tokenizer（斷詞）
與直譯器相同——把程式碼拆成 Token。
C-L2 — 直接改造 eval() 為 emit()，輸出 Bytecode 而非直接執行
↓
2
AST（語法樹）
與直譯器相同——將 Token 組裝成語法樹。編譯器同樣需要語法樹來理解程式結構。
C-L3 — 加入符號表（Symbol Table），支援變數：x = 5 → STORE 0
↓
3
Bytecode（位元組碼）
遍歷 AST，根據每個節點的類型輸出對應的指令。每一個指令只是一個數字或一個地址。
C-L2 — 基本運算：1 + 2 * 3 = 7
1 + 2 * 3 →
IMM 1　; push 1
IMM 2　; push 2
IMM 3　; push 3
MUL　　; pop 3,2 → push 6
ADD　　; pop 6,1 → push 7
↓
4
VM（虛擬機器）
Bytecode 不是給真實 CPU 看的，而是給軟體做出來的虛擬機器看。VM 就是一個只懂 Bytecode 的模擬計算機。
C-L4 — 支援 while 迴圈：JMP/JMP_FALSE 控制流程跳轉
C-L5 — 支援函數：CALL/RET 建立呼叫堆疊（Call Stack）

編譯器 Level 递进邏輯

C-L1
編譯器概念——從直譯器過渡到編譯器，理解「翻譯一本書」的概念：先翻譯，之後再執行。
C-L2
基本運算——改造 eval() 為 emit()。每一個 AST 節點不再直接計算，而是輸出對應的 Bytecode 指令。
C-L3
變數支援——為什麼需要符號表？Bytecode 的 STORE/LOAD 用索引值（不是名稱），需要一個表格把變數名稱映射到索引。
C-L4
while 迴圈——為什麼需要 JMP/JMP_FALSE？迴圈的本質是「滿足條件就跳回去」。Bytecode 用跳轉指令模擬控制流程。
C-L5
函數與 Call Stack——為什麼需要 Frame？每一次函數呼叫需要：保存返回地址、建立新作用域、搬移參數。Frame 讓這些操作結構化。
⭐ 關鍵：編譯器有「寫入檔案」這步

原始碼 → 編譯器 → Bytecode 檔案 → VM 讀取執行。多了「中間產物」，可以脫離編譯器獨立存在。

Bytecode 指令集

CalcLang 的 VM 基於 Stack 架構，所有運算都透過堆疊完成。壓入（push）彈出（pop）是基本操作單位。

Opcode 格式 說明 範例
IMM IMM n 將立即值 n 壓入堆疊頂端 IMM 5 → push 5

IMM — 載入立即值（Immediate）

VM 語意

IMM n 將常數 n 直接壓入 stack頂端，是 CalcLang 中唯一會把具體數值放進程式的指令。所有變數的初始值、運算元、迴圈次數，都需要先用 IMM 載入。 

; 計算 10 + 20
IMM 10       ; push 10
IMM 20       ; push 20
ADD          ; pop 20 + pop 10 = push 30
PRINT        ; 輸出: 30

; 初始化的過程就是連續 IMM
IMM 0        ; 初始化計數器
IMM 100      ; 設定上限
LOAD LOAD idx 將變數陣列第 idx 個元素壓入堆疊 LOAD 0 → push vars[0]

LOAD — 讀取變數（Load from Variable）

VM 語意

LOAD idx 從 VM 的變數陣列 vars[idx] 讀取內容並 push 到 stack。相當於「把變數的值取出來繼續運算」。每次使用變數前，都需要先 LOAD 才能取得其中的數值。 

; x = 5 之後，取出計算
IMM 5        ; 將 5 壓入 stack
STORE 0      ; pop → vars[0] = 5

LOAD 0       ; push vars[0] → push 5
IMM 3        ; push 3
ADD          ; pop 3 + pop 5 = push 8
PRINT        ; 輸出: 8
STORE STORE idx 彈出堆疊頂端，存入變數陣列第 idx 格 STORE 0 → pop → vars[0]

STORE — 寫入變數（Store to Variable）

VM 語意

STORE idx 從 stack pop 一個值，存入變數陣列 vars[idx]。這是 CalcLang 中「賦值」的唯一方式——先把表達式結果算出來，再用 STORE 寫入變數。 

; x = 10 + 5
IMM 10       ; push 10
IMM 5        ; push 5
ADD          ; pop 5 + pop 10 = push 15
STORE 0      ; pop → vars[0] = 15

; 完整賦值流程：先 IMM/LOAD 算出值，再 STORE 寫入
IMM 3        ; 計算 3*4
IMM 4
MUL          ; push 12
STORE 1      ; y = 12
ADD ADD 彈出兩個值相加，結果壓回堆疊 push 1, push 2 → ADD → push 3

ADD — 加法

VM 語意

ADD 從 stack pop 兩個值（先右側再左側）相加，結果 push 回 stack。計算是：左側 + 右側。結果壓回後可用於繼續運算或馬上列印。 

; 1 + 2
IMM 1        ; push 1
IMM 2        ; push 2
ADD          ; pop 2 + pop 1 = push 3
PRINT        ; 輸出: 3

; 鏈式計算：1 + 2 + 3 + 4
IMM 1
IMM 2
ADD          ; push 3
IMM 3
ADD          ; push 6
IMM 4
ADD          ; push 10
PRINT        ; 輸出: 10
SUB SUB 彈出兩個值相減（先 pop 右側，再 pop 左側） push 5, push 2 → SUB → push 3

SUB — 減法

VM 語意

SUB pop 兩個值後計算「左側 − 右側」，結果 push 回 stack。左側 是第二次 pop 的值，右側 是第一次 pop 的值。 

; 10 - 3 = 7
IMM 10       ; push 10（左側）
IMM 3        ; push 3（右側）
SUB          ; pop 3（左）-pop 10（右）= push 7
PRINT        ; 輸出: 7

; 鏈式：10 - 3 - 2 = 5
IMM 10
IMM 3
SUB          ; push 7
IMM 2
SUB          ; pop 2（左）-pop 7（右）= push 5
PRINT        ; 輸出: 5
MUL MUL 彈出兩個值相乘，結果壓回堆疊 push 2, push 3 → MUL → push 6

MUL — 乘法

VM 語意

MUL pop 兩個值相乘（左側 × 右側），結果 push 回 stack。乘法比除法優先順序相同，但都高於加法和減法。 

; 3 × 4 = 12
IMM 3
IMM 4
MUL          ; pop 4 × pop 3 = push 12
PRINT        ; 輸出: 12

; 計算面積：寬 × 高
IMM 5        ; 寬度 5
IMM 8        ; 高度 8
MUL          ; push 40（面積）
PRINT        ; 輸出: 40
DIV DIV 彈出兩個值相除（先 pop 右側，再 pop 左側） push 8, push 2 → DIV → push 4

DIV — 除法

VM 語意

DIV pop 兩個值後計算「左側 ÷ 右側」，結果 push 回 stack。只做整數除法，小數部分會截斷（不是四捨五入）。 

; 10 / 3 = 3（整數除法）
IMM 10
IMM 3
DIV          ; pop 3（左）÷ pop 10（右）= push 3
PRINT        ; 輸出: 3

; 複合計算：(8 + 2) / 2 = 5
IMM 8
IMM 2
ADD          ; push 10
IMM 2
DIV          ; push 5
PRINT        ; 輸出: 5
CMP_LT CMP_LT 比較是否小於，結果為 1（真）或 0（假） push 2, push 5 → CMP_LT → push 1

CMP_LT — 比較小於（Less Than）

VM 語意

CMP_LT pop 兩個值，檢查「左側 < 右側」是否為真。結果為 1（真）或 0（假），用於控制流程中的條件判斷。 

; if (3 < 5) 列印 1，否則列印 0
IMM 3        ; 左側
IMM 5        ; 右側
CMP_LT       ; push 1（3 < 5 成立）
PRINT        ; 輸出: 1

; 與 JMP_FALSE 搭配實現條件分支
IMM 10
IMM 20
CMP_LT       ; push 0（10 < 20 成立 → 結果為 1）
JMP_FALSE skip ; 結果為 1，不跳轉，繼續執行
PRINT        ; 輸出: 1
CMP_GT CMP_GT 比較是否大於 push 2, push 5 → CMP_GT → push 0

CMP_GT — 比較大於（Greater Than）

VM 語意

CMP_GT pop 兩個值，檢查「左側 > 右側」是否為真。與 CMP_LT 相反，但同樣輸出 1（真）或 0（假）。 

; 10 > 5 → 1
IMM 10
IMM 5
CMP_GT       ; push 1（10 > 5 成立）
PRINT        ; 輸出: 1

; 5 > 10 → 0
IMM 5
IMM 10
CMP_GT       ; push 0（5 > 10 不成立）
PRINT        ; 輸出: 0
CMP_EQ CMP_EQ 比較是否相等 push 3, push 3 → CMP_EQ → push 1

CMP_EQ — 比較相等（Equal）

VM 語意

CMP_EQ pop 兩個值，檢查「左側 == 右側」是否相等。相等輸出 1，否則輸出 0。常用於等號判斷、迴圈終止條件。 

; 5 == 5 → 1
IMM 5
IMM 5
CMP_EQ       ; push 1（相等）
PRINT        ; 輸出: 1

; 5 == 3 → 0
IMM 5
IMM 3
CMP_EQ       ; push 0（不相等）
PRINT        ; 輸出: 0

; while (x != 0) 的終止條件
LOAD 0       ; 讀取 x
IMM 0
CMP_EQ       ; x == 0 ?
JMP_FALSE loop ; 不為 0，繼續迴圈
JMP JMP addr 無條件跳躍到指定地址 JMP 4 → PC = 4

JMP — 無條件跳躍（Jump）

VM 語意

JMP addr 直接修改 PC（程式計數器）為指定地址，VM 下一個執行週期會跳到該位址繼續執行。常用於迴圈、無條件分支。 

; 無限迴圈（while 1）
label start
IMM 1        ; 這行位址 0
PRINT        ; 位址 1
JMP start    ; PC 跳回位址 0，繼續執行

; if-else 的跳過分支
CMP_EQ       ; 結果在 stack
JMP_FALSE else_part ; 為 0，跳到 else
PRINT        ; then 分支
JMP end
label else_part
PRINT        ; else 分支
label end
JMP_FALSE JMP_FALSE addr 若堆疊頂為 0，跳到指定地址；否則繼續執行下一條 push 0 → JMP_FALSE 10 → PC = 10

JMP_FALSE — 條件跳躍（Jump if False）

VM 語意

JMP_FALSE addr 先 pop stack 頂端的值，若為 0（假），則跳到指定地址；若為 非0（真），則繼續執行下一條指令。搭配 CMP_* 指令使用，實現 if / while 等控制流程。 

; while (x < 10) { print x }
; 假設 x 已在 vars[0]，位址 5 是 loop 入口
LOAD 0       ; push x
IMM 10
CMP_LT       ; push 1（假）或 0（真）
JMP_FALSE exit ; 為 0（條件為假）時跳出迴圈
PRINT
JMP loop     ; 繼續下一次迴圈

label exit
; 迴圈結束

; if (x > 0) print 1 else print 0
LOAD 0
IMM 0
CMP_GT       ; x > 0 ?
JMP_FALSE else ; 為 0，跳到 else
IMM 1
PRINT        ; then: 輸出 1
JMP end
label else
IMM 0
PRINT        ; else: 輸出 0
label end
CALL CALL addr 建立新 Frame（保存返回地址、跳轉到函數入口） CALL 20 → frame.push(PC+1), PC=20

CALL — 函數呼叫（Call Function）

VM 語意

CALL addr 將下一條指令的位址（PC+1）存入 Call Frame，再跳到函數入口執行。RET 時會取出返回位址繼續執行。支援巢狀函數呼叫。 

; 呼叫函數 foo（假設入口在位址 5）
IMM 10       ; 準備參數
CALL foo     ; frame.push(PC+1=下一條), PC=5
PRINT        ; 函數返回後繼續執行這裡

label foo
; 函數內容在這裡
RET          ; frame.pop() → PC 返回

; 巢狀呼叫
CALL a       ; 進入 a
label a
CALL b       ; 再進入 b
label b
RET          ; 返回 a
RET          ; 返回 main
RET RET 函數返回——彈出 Frame，恢復返回地址 RET → frame.pop(), PC=ret_addr

RET — 函數返回（Return）

VM 語意

RET 從 Call Frame stack pop 返回位址，恢復 PC（程式計數器），讓 VM 跳回函數呼叫處的下一條指令繼續執行。每一個 CALL 都必須有對應的 RET，否則 VM 無法正確返回。 

; 簡單的返回範例
CALL my_func ; 位址 0 → 跳到位址 5
PRINT        ; 位址 2 → 函數返回後執行這裡（PC=2）

label my_func ; 位址 5
IMM 99
PRINT        ; 輸出 99
RET          ; pop ret_addr=2 → PC=2，繼續執行
PRINT PRINT 彈出堆疊頂端並輸出 push 7 → PRINT → 輸出 7

PRINT — 輸出堆疊頂端

VM 語意

PRINT 從 stack pop 頂端值並輸出（printf）。不改變 stack 內容（只是取出）。常用於顯示計算結果、變數值、函數回傳值。 

; 基本輸出
IMM 42
PRINT        ; 輸出: 42

; 輸出字串（Compiler 版本）
; 字串在 Compiler 中是直接作為資料印出

; 鏈式計算並輸出
IMM 1
IMM 2
ADD          ; push 3
PRINT        ; 輸出: 3

; 印出多個值
IMM 10
IMM 20
ADD          ; push 30
PRINT        ; 輸出: 30
EOF EOF 程式結束，VM 停止 —

EOF — 程式結束（End of File）

VM 語意

EOF 是 VM 的停止訊號。執行到此指令時，VM 結束執行迴圈並輸出 VM done.。每個 CalcLang 程式都必須以 EOF 結尾，否則 VM 會繼續執行記憶體中剩餘的垃圾資料，導致未定義行為。 

; 完整程式範例：1 + 2
IMM 1
IMM 2
ADD
PRINT
EOF          ; VM 停止，輸出 "VM done."

; 沒有 EOF 的風險
; IMM 1
; IMM 2        ← VM 可能會把這些當成指令執行
; ADD          ← 導致錯誤輸出或當機

直譯器 vs 編譯器

兩者的前半段（Tokenizer + AST）完全相同，差異從「如何執行」這一步開始分道揚鑣。

直譯器（Interpreter） 編譯器（Compiler）
核心差異 直接執行 AST 把 AST 編譯成 Bytecode 再執行
執行方式 一邊翻譯一邊執行，翻譯完就執行完 先完整翻譯成檔案，未來隨時可執行
輸出 沒有輸出檔案 產生 .byte 或 .bin 中間檔
速度 啟動快，每次執行都要重新翻譯 啟動慢（需先載入 Bytecode），但執行穩定
跨平台 依賴直譯器本身（需針對每個平台編譯） 只需移植 VM（Bytecode 是平台無關的）
類似例子 Python、Ruby、JavaScript C、C++、Java（.class）、Lua
