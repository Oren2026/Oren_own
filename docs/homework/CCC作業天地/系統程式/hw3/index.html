為什麼要強化 CalcLang

黑皮：
老師說 HW3 要做一個軟體專案，或延伸其他專案修改。那如果我們就把 HW2 的編譯器繼續延伸，加入新功能讓它變得更強大？
黑輪：
像是加入 fork、file I/O、time、rand 這類系統層面的功能？讓它從純計算機變成一個真正可以「做事」的腳本語言？
黑皮：
對，而且可以用 HW2 當基礎，變成 HW3。這樣 HW2 的內容就不只是計算機了，而是一個可以持續成長的系統。
⭐ 目標：從「計算機」升級成「腳本語言」

HW3 在 HW2 的基礎上，新增程序控制、檔案 I/O、時間與睡眠、亂數、字串操作等功能，讓 Solang 不只是計算，而是可以做任何事。

HW3 新功能總覽

程序控制（Process Control）

FORK：fork() 程序複製，建立子程序 / EXIT：結束程式並返回 exit code / EXEC：執行外部命令

標準輸出入（I/O）

PRINT / PRINTLN：輸出字串（不換行/換行）/ READ：讀取一行 stdin

檔案 I/O（File Operations）

FOPEN / FREAD / FWRITE / FCLOSE：開啟、讀取、寫入、關閉檔案

時間與亂數（Time & Random）

TIME：取得目前時間戳 / SLEEP：暫停執行 / RAND：產生亂數

字串操作（String Operations）

STRLEN：回傳字串長度 / STRCMP：比較兩字串 / INT_TO_STR：整數轉字串

HW3 新增 Bytecode 指令

以下指令在 HW2 的基礎上新增（Opcode 13-28）。HW2 的指令（0-12）仍然完整保留。

Opcode 名稱 參數 說明 範例
13 FORK — fork() 程序複製，回傳子程序 PID，0 表示在子程序中 fork() → push 12345（子 PID）

13 FORK — 程序複製

介紹

FORK 是 Unix/Linux 系統中最重要的系統呼叫之一，用於複製當前程序（父程序），產生一個幾乎完全相同的副本（子程序）。兩者從同一個記憶體狀態繼續執行，但各自有獨立的 PID。

系統層面發生了什麼
父程序調用 fork()
        ↓
作業系統複製父程序的完整狀態：
  - 記憶體內容（程式碼、全域變數、堆疊）
  - 暫存器狀態
  - 檔案描述符（繼承）
        ↓
+-------------------+-------------------+
|      父程序        |      子程序        |
| fork() 回傳       | fork() 回傳       |
| 子程序的 PID (>0) | 0                 |
+-------------------+-------------------+
VM 語意
FORK 將結果 push 到 stack：
  • 在父程序：push <子程序 PID>（正整數）
  • 在子程序：push 0
使用範例
; 測量子程序是否為子程序
FORK        ; push 0 (子) 或 12345 (父)
DUP         ; 複製 stack 頂端
JZ child    ; 如果是 0（子程序），跳到 child 標籤

; 父程序邏輯
PRINT("Parent: child PID=")
PRINTLN()  ; 印出子 PID

; 子程序邏輯
label child
PRINTLN("I am child")
EXIT(0)

; 等待子程序結束
WAIT         ; 等待子程序並取得 exit code
14 EXIT code exit(code)，結束程式並返回 exit code push 0 → exit → 正常結束

14 EXIT — 結束程式

介紹

EXIT 是程式的正常出口，用於結束目前程序的執行並回傳一個 exit code（離開碼）給父程序。Convention：0 表示正常結束，非 0 表示異常。

系統層面發生了什麼
程式調用 exit(exit_code)
        ↓
作業系統做的事情：
  1. 關閉所有開啟的檔案描述符
  2. 釋放記憶體（heap、stack）
  3. 將 exit_code 寫入 PCB（程序控制區塊）
  4. 向父程序發送 SIGCHLD 訊號
  5. 程式從行程表中移除（進入 Zombie 狀態等待父程序撿收）
        ↓
父程序可透過 wait() 取得 exit_code
VM 語意
EXIT 從 stack pop exit code 並終止 VM：
  • pop exit_code → 作為程式結束碼
  • 0 = 正常結束，非 0 = 異常或錯誤碼
使用範例
; 正常結束
push 0
EXIT        ; exit(0) → 程式正常結束

; 錯誤結束
push 1
EXIT        ; exit(1) → 程式異常結束

; 結合 IF 判斷
push 100
DUP
push 0
JGT error   ; 如果 > 0，跳到 error 標籤

; 正常流程結束
push 0
EXIT

label error
push 1
EXIT        ; 帶錯誤碼 1 結束
15 EXEC str_idx 執行外部命令（system()），結果壓入堆疊 EXEC("echo hello") → push 0

15 EXEC — 執行外部命令

介紹

EXEC 是 Unix 系統的核心系統呼叫，用於以新程式替換當前行程的執行映像。在 Solang VM 中，透過 system() 實現，執行 Shell 命令並取得其回傳值。

系統層面發生了什麼
EXEC("ls -la")
        ↓
1. 在字串池中找到命令 "ls -la"
2. 呼叫 system("ls -la")
   system() 內部：fork() + execvp() + wait()
        ↓
+-------------------+-------------------+
|      父程序        |      子程序        |
| 等待 execvp()      | execvp("ls -la")  |
| 執行完畢           | 執行 ls -la       |
+-------------------+-------------------+
        ↓
system() 回傳 ls 的 exit code
        ↓
push 到 VM stack
VM 語意
EXEC 讀取字串池中的命令並執行：
  • 從 stack pop 命令的字串池索引 str_idx
  • 執行 system(string_pool[str_idx])
  • 將 exit code push 回 stack（0 = 成功）
使用範例
; 執行 ls 命令
EXEC("ls")

; 執行並判斷是否成功
EXEC("mkdir testdir")
DUP
JZ mkdir_failed   ; 如果是 0（失敗），跳至錯誤處理

PRINTLN("目錄建立成功")
JMP done

label mkdir_failed
PRINTLN("目錄建立失敗")

label done
; 執行多個指令（用分號串接）
EXEC("gcc -o prog main.c && ./prog")

; 讀取系統資訊
EXEC("uname -a")
EXEC("date")
16 PRINT str_idx 輸出字串（不換行） PRINT("Hello ") → Hello

16 PRINT — 輸出字串（不換行）

介紹

PRINT 從字串池取出指定索引的字串，輸出到標準輸出（stdout），輸出後不換行，游標留在結尾。適合需要連續輸出多個片段的場景（如橫向列表、格式化輸出）。

VM 語意
  • 從 stack pop 字串池索引 str_idx
  • 從 string_pool[str_idx] 取得字串
  • 輸出至 stdout，不自動換行
使用範例
; 基本用法
PRINT("Hello ")    ; 輸出: Hello[游標在這裡]
PRINT("World")     ; 輸出: HelloWorld[游標在這裡]
PRINTLN("!")       ; 輸出: HelloWorld![換行]

; 橫向列表
PRINT("Item 1: ")
PRINTLN("apple")

PRINT("Item 2: ")
PRINTLN("banana")

; 搭配整數輸出
PRINT("Result = ")
; 這裡需要先將整數轉成字串再印出
INT_TO_STR(42)
PRINTLN()          ; 輸出: Result = 42
17 PRINTLN str_idx 輸出字串（換行） PRINTLN("World") → World[newline]

17 PRINTLN — 輸出字串（換行）

介紹

PRINTLN 與 PRINT 相同，但輸出後自動附加換行字元（\n），每條訊息各自佔一行，適合大多數日常輸出場景。

VM 語意
  • 從 stack pop 字串池索引 str_idx
  • 從 string_pool[str_idx] 取得字串
  • 輸出至 stdout 並附加 \n（自動換行）
使用範例
; 基本用法
PRINTLN("Hello")    ; 輸出: Hello[換行]
PRINTLN("World")    ; 輸出: World[換行]

; 訊息輸出
PRINTLN("=== 程式開始 ===")
PRINTLN("讀取檔案中...")
PRINTLN("完成！")

; 錯誤訊息
PRINTLN("Error: 檔案不存在")
PRINTLN("請確認路徑是否正確")

; PRINT vs PRINTLN 差異
PRINT("No newline")   ; 輸出: No newline[游標在這]
PRINTLN("With newline") ; 輸出: With newline[換行]
18 READ — 讀取一行 stdin，回傳字串索引 READ → push 0（字串池索引）

18 READ — 讀取一行 stdin

介紹

READ 從標準輸入（stdin）讀取一行文字，使用者需按下 Enter 鍵才算完成。讀取的內容會存入字串池，並將該字串的索引 push 到 stack。

VM 語意
  • 呼叫 fgets() 或 gets() 讀取一行
  • 將讀到的字串存入 string_pool
  • 將字串池索引 push 到 stack（可用 PRINTLN 或 STRLEN 等指令操作）
  • 若讀取失敗（EOF），push -1
使用範例
; 基本互動程式
PRINTLN("請輸入您的名字：")
READ           ; 等待使用者輸入並按 Enter
; stack: [字串池索引]

; 讀取並顯示
PRINT("您輸入的是：")
PRINTLN()      ; 印出剛才 READ 的內容

; 讀取並運算
PRINTLN("請輸入第一個數字：")
READ
; 這裡需要將讀到的數字字串轉成整數做計算
; 示範基本互動對話
PRINTLN("=== 使用者互動範例 ===")
PRINTLN("請輸入您的名字：")
READ
PRINT("您好，")
PRINTLN()
PRINTLN("歡迎使用 Solang VM！")
19 FOPEN fn_idx + mode_idx fopen(filename, mode)，回傳檔案指標（-1 表示失敗） FOPEN("test.txt", "r") → push 0x1000

19 FOPEN — 開啟檔案

介紹

FOPEN 是標準 C 函式 fopen() 的封裝，用於開啟一個檔案並取得檔案指標（File Pointer）。這個指標後續會用於讀取（FREAD）、寫入（FWRITE）、關閉（FCLOSE）該檔案。開啟失敗時回傳 -1。

檔案模式（mode）
mode意義
"r"唯讀，檔案需存在
"w"唯寫，不存在則新建，存在則截斷
"a"附加，寫入從檔尾開始
"r+"讀寫，檔案需存在
"w+"讀寫，不存在則新建
"a+"讀寫附加，讀取從頭，寫入從尾
VM 語意
  • HW3 將 filename_idx（左 8 bits）和 mode_idx（右 8 bits）封裝成一個 16-bit 參數
  • pop 該參數後解封裝，取出兩個字串池索引
  • 呼叫 fopen(filename, mode)
  • 成功：push 檔案指標（指標位址）；失敗：push -1
使用範例
; 開啟檔案讀取
FOPEN("data.txt", "r")
DUP
JZ open_failed   ; 如果是 -1（失敗），跳至錯誤處理

; 開啟檔案寫入（不存在會新建）
FOPEN("output.txt", "w")
DUP
JZ write_failed

; 開啟檔案附加
FOPEN("log.txt", "a")

label open_failed
PRINTLN("錯誤：無法開啟檔案")

label write_failed
PRINTLN("錯誤：無法寫入檔案")
20 FREAD fp fgets 讀一行，回傳字串索引（-1 表示失敗） FREAD(fp) → push 1（讀到內容）

20 FREAD — 讀取檔案一行

介紹

FREAD 使用 fgets() 從已開啟的檔案指標讀取一行文字（遇到 \n 或 EOF 為止）。讀取的內容存入字串池，回傳索引至 stack。常用於逐行處理文字檔。

VM 語意
  • 從 stack pop 檔案指標 fp
  • 呼叫 fgets(buffer, MAX_LINE, fp)
  • 將該行存入字串池，push 索引到 stack
  • 成功：push 字串池索引；失敗（EOF/錯誤）：push -1
使用範例
; 開啟並逐行讀取
FOPEN("data.txt", "r")
JZ open_failed

; 迴圈讀取直到 EOF
label read_loop
FREAD            ; 讀取一行
DUP
push -1
JEQ end_of_file  ; 如果是 -1，到檔案結尾

; 處理讀到的行
PRINT("讀到：")
PRINTLN

JMP read_loop

label end_of_file
FCLOSE           ; 關閉檔案

label open_failed
PRINTLN("無法開啟檔案")
21 FWRITE fp, str_idx 寫入字串到檔案，回傳 0（成功）或 -1（失敗） FWRITE(fp, str) → push 0

21 FWRITE — 寫入字串到檔案

介紹

FWRITE 將字串寫入已開啟的檔案，使用 fputs() 實作。寫入後，游標位置隨之移動。常用於將程式執行結果或日誌寫入磁碟。

VM 語意
  • 從 stack pop 檔案指標 fp
  • 從 stack pop 字串池索引 str_idx
  • 呼叫 fputs(string_pool[str_idx], fp)
  • 成功：push 0；失敗：push -1
使用範例
; 開啟並寫入
FOPEN("output.txt", "w")
JZ write_failed

; 寫入多行文字
FWRITE            ; fp 在 stack
"Line 1: Hello\n"
FWRITE
"Line 2: Solang\n"

PRINTLN("寫入完成")

label write_failed
PRINTLN("錯誤：寫入失敗")
22 FCLOSE fp fclose，回傳 0（成功）或 -1（失敗） FCLOSE(fp) → push 0

22 FCLOSE — 關閉檔案

介紹

FCLOSE 關閉已開啟的檔案，緩衝區內尚未寫入的資料會先 flush 寫入磁碟，並釋放該檔案指標。完成所有檔案操作後，必須關閉檔案以確保資料寫入且不泄漏檔案描述符。

VM 語意
  • 從 stack pop 檔案指標 fp
  • 呼叫 fclose(fp)
  • 成功：push 0；失敗：push -1
使用範例
; 完整檔案操作流程
FOPEN("data.txt", "r")
JZ failed

; ... 讀取或寫入操作 ...

FCLOSE
PRINTLN("檔案已關閉")

; 錯誤處理
label failed
PRINTLN("無法開啟檔案")
push 1
EXIT
23 TIME — time(NULL)，回傳目前時間戳（int） TIME → push 1779981484

23 TIME — 取得目前時間戳

介紹

TIME 呼叫系統函式 time(NULL)，回傳自 1970-01-01 00:00:00 UTC 起經過的秒數（Unix Epoch）。常用於計算時間差、生成唯一ID、或作為亂數生成器的 seed。

VM 語意
  • 呼叫 time(NULL)
  • 將回傳的 time_t 值（秒數）push 到 stack
  • 無參數，不 pop 任何值
使用範例
; 取得目前時間戳
TIME
PRINTLN           ; 輸出：1700000000（Unix 時間戳）

; 時間戳的用途
PRINTLN("=== 時間戳應用 ===")
TIME               ; push 時間戳
; 可用於：
; - 計算程式執行時間
; - 為 RAND 提供 seed
; - 生成不重複ID

; 顯示時間戳含義
TIME
PRINTLN(" Unix 時間戳（秒）")
PRINTLN("從 1970-01-01 起算")
24 SLEEP sec sleep(sec)，暫停執行秒數 SLEEP(1) → 暫停 1 秒

24 SLEEP — 暫停執行

介紹

SLEEP 呼叫系統函式 sleep(sec)，讓 VM暫停指定秒數後再繼續執行。常用於需要延遲的場景：等待外部資源、冷卻計時、動畫延時、或批次作業的間隔。

VM 語意
  • 從 stack pop 秒數 sec
  • 呼叫 sleep(sec) 暫停行程
  • 暫停結束後繼續執行，無回傳值
使用範例
; 倒數計時
PRINTLN("倒數開始：")
push 3
label countdown
DUP
JZ done
PRINTLN
push 1
SUB
SLEEP             ; 暂停 1 秒
JMP countdown

label done
PRINTLN("時間到！")

; 批次作業間隔
PRINTLN("處理中...")
SLEEP             ; 假設前面 push 了 2
PRINTLN("完成")
25 RAND max rand() % max，回傳 0 到 max-1 的亂數（max=0 時預設 100） RAND(6) → push 3（擲骰子）

25 RAND — 亂數產生

介紹

RAND 呼叫 rand() 並取 max 的模數，回傳 [0, max-1] 範圍內的亂數。常用於遊戲（擲骰子、抽卡）、模擬、隨機測試資料生成等場景。

VM 語意
  • 從 stack pop max
  • 呼叫 rand() % max
  • 若 max == 0，預設使用 100（回傳 0~99）
  • push 亂數結果到 stack
使用範例
; 擲骰子（1~6）
RAND(6)             ; 回傳 0~5
push 1
ADD
PRINTLN            ; 輸出 1~6

; 亂數範圍技巧
; 要取得 1~max（含）：RAND(max) + 1
; 要取得 min~max（含）：RAND(max-min+1) + min

; 遊戲範例
PRINTLN("擲骰子：")
RAND(6)             ; 0~5
push 1
ADD
PRINTLN

PRINTLN("隨機顏色：")
RAND(3)             ; 0~2
; 0=紅, 1=綠, 2=藍
; 根據數值做不同處理
26 STRLEN str_idx 回傳字串長度 STRLEN("hello") → push 5

26 STRLEN — 取得字串長度

介紹

STRLEN 從字串池取出指定字串，回傳其長度（不包括結尾的 \0）。常用於驗證輸入、計算迴圈次數、動態配置記憶體等場景。

VM 語意
  • 從 stack pop 字串池索引 str_idx
  • 呼叫 strlen(string_pool[str_idx])
  • push 長度（int）到 stack
使用範例
; 測量字串長度
STRLEN             ; 假設 stack 頂是 "hello"
PRINTLN            ; 輸出: 5

; 驗證輸入長度
PRINTLN("請輸入密碼：")
READ
STRLEN
push 8
JLT password_short  ; 小於 8 字元

label password_short
PRINTLN("密碼太短")

; 搭配迴圈處理每個字元
STRLEN
DUP
JZ empty_string
; 迴圈處理...
27 STRCMP idx1, idx2 比較兩字串，回傳 0（相等）、正數或負數 STRCMP("a","b") → push -1

27 STRCMP — 字串比較

介紹

STRCMP 呼叫標準 C 的 strcmp()，依字典順序比較兩個字串。常用於密碼驗證、命令解析、條件分支（if/case）等場景。

VM 語意
  • 從 stack pop idx2（第二個字串）和 idx1（第一個字串）
  • 呼叫 strcmp(string_pool[idx1], string_pool[idx2])
  • 結果：0 = 相等，正數 = idx1 > idx2，負數 = idx1 < idx2
  • push 比較結果到 stack
使用範例
; 基本相等判斷
STRCMP              ; 比較棧頂兩個字串
JZ equal            ; 結果為 0，跳到 equal

PRINTLN("不相等")

label equal
PRINTLN("相等")

; 命令解析
PRINTLN("請輸入指令：")
READ
STRCMP("quit")
JZ exit_program

; 密碼驗證
READ                 ; 讀取使用者輸入密碼
STRCMP("secret123")  ; 比較
JZ login_success

label login_success
PRINTLN("登入成功")
JMP done

label exit_program
PRINTLN("再見！")
push 0
EXIT
28 INT_TO_STR val 整數轉字串，結果存入字串池，回傳索引 INT_TO_STR(42) → push 2（"42"）

28 INT_TO_STR — 整數轉字串

介紹

INT_TO_STR 將整數轉換為可顯示的字串，結果存入字串池並回傳索引。這讓 VM 能輸出計算結果、格式化訊息，或將數值寫入檔案。屬於 HW3 新增的最後一個指令。

VM 語意
  • 從 stack pop 整數 val
  • 呼叫 sprintf() 將整數格式化為字串
  • 將新字串存入字串池，push 該字串池索引到 stack
  • 該索引可用於 PRINTLN、FWRITE 等需要字串的操作
使用範例
; 輸出計算結果

push 200
ADD                  ; 計算 100+200=300
INT_TO_STR           ; 轉成 "300"
PRINTLN              ; 輸出: 300

; 格式化輸出訊息

push 42
INT_TO_STR
PRINTLN              ; 輸出: 結果：42

; 將數值寫入檔案
FOPEN("data.txt", "w")
FWRITE               ; 寫入 "42"
FCLOSE

; 實用：計算並顯示
PRINTLN("1+2+3+4+5 =")
push 1
push 2
ADD
push 3
ADD
push 4
ADD
push 5
ADD
INT_TO_STR
PRINTLN              ; 輸出: 1+2+3+4+5 = 15

VM 架構說明

HW3 的 VM 基於 HW2 的 Stack VM 改造而來，加入了以下新元件：

String Pool（字串池）

所有字串（包括 PRINT/EXEC 的內容、FOPEN 的檔案名稱與模式）都存在 String Pool 裡，以索引值存取。這樣可以讓 Bytecode 只帶數字索引，不需要攜帶完整字串。

FOPEN 參數封裝

FOPEN 需要兩個字串參數（filename 和 mode）。HW3 用一個 16-bit 整數打包：filename_idx 放高 8 bits，mode_idx 放低 8 bits。解讀時用 (arg >> 8) & 0xFF 取 filename，(arg & 0xFF) 取 mode。

FORK 的父子程序模型

fork() 以後，父子程序各自從同一個 VM 狀態繼續執行。區分方式是：fork() 回傳值在子程序是 0，在父程序是子程序的 PID。
