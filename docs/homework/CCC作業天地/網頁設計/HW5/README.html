核心概念
一個在瀏覽器裡就能跑的日誌系統，從初版一路演化到 v3.0。前端用 JavaScript + sql.js（SQLite 的 WASM 版）實作，後期加入 Node.js 後端對照版。前端版本無需安裝任何東西，開了瀏覽器就能用。
純前端 SQLite (WASM) 本地持久化 亮暗主題 SPA 路由 Hash 模式
功能總覽
🌙

亮 / 暗版主題

一鍵切換亮版與暗版，CSS 變數驅動，無需重整頁面。

👥

作者追蹤系統

可追蹤 / 取消追蹤作者，有自己的個人頁（`/#/profile/:username`），顯示粉絲數、追蹤數、文章列表。

🔗

Hash SPA 路由

純前端路由，無需後端支援，URL 直接分享到特定頁面。

🔐

JWT 身份驗證

Node.js 後端版支援 JWT，bcrypt 密碼雜湊，完整的使用者系統。

🗄️

本地優先儲存

sql.js + IndexedDB，資料存在瀏覽器本地，關掉後端也能完整使用（試用模式）。

🎨

自定義個人頁

可自行設定頭像色彩、背景圖、暱稱與自我介紹。

💬 與 AI 的討論過程
v1.0 — 初版
黑皮
我想做一個可以在瀏覽器跑的日誌系統，不需要伺服器那種
Hermes
建議用 sql.js（SQLite 的 WebAssembly 版），資料存在 IndexedDB，關掉瀏覽器後還在。不需要任何後端就能跑。
黑皮
好，那就用 sql.js，先做基本 CRUD 和搜尋功能
→ 决策：純前端 SQLite，無需後端依赖
v1.1 — 雙面板 Auth + 公開日誌牆
黑皮
想要有一個大家都看得到的日誌牆，但也可以登入有自己的內容
Hermes
建議用「雙面板 Auth Modal」——未登入時看到公開日誌牆，點登入後出現浮動面板切換登入/註冊，切換時 label 會有動態位移。
黑皮
這樣不錯，先做示範資料，讓老師打開就能看到效果
→ 决策：雙面板 Auth + seed.db 預設資料
v1.2 — 作者過濾
黑皮
想要點作者名字就能只看那個人的文章
Hermes
實作方式：點擊作者名稱時，在 posts 查詢時加一個 WHERE author = ? 的條件；右上角顯示目前過濾狀態，可以一鍵清除。
黑皮
OK，就用那個方式
→ 决策：作者名稱作為即時過濾器，右上角顯示篩選狀態
v1.3 — DB class 重構 + 安全性
黑皮
之前都是直接字串拼接 SQL，現在數據多了感覺不太安心
Hermes
SQL 注入攻擊是真实風險。建議全面改用參數化查詢，封裝一個 DB class：`db.get() / db.all() / db.run()`，所有 SQL 字串中都杜絕字串拼接。
黑皮
好，重構起來。以後每個 query 都用參數化
→ 决策：DB class 封裝 + 全面參數化查詢
v2.0 — Node.js 後端對照版
黑皮
想對照看一下，前端 sql.js 版本和真實後端版本差在哪
Hermes
建議用 Express + SQLite（better-sqlite3）+ bcrypt 密碼雜湊 + JWT 身份驗證，前端介面盡量保持不變，方便兩邊對照。
黑皮
好，那就做一個後端版，功能盡量跟前端的差不多
→ 决策：Express + bcrypt + JWT，前端介面一致
v2.1 — 試用模式 + Morgan 日誌
黑皮
有時候想展示但沒有辦法開後端，能不能讓前端也能獨立跑？
Hermes
可以做一個「試用模式」：當後端沒有啟動時，前端 fetch 全部 mock（demo.js），開關後端時自動切換，不需要手動切換。
黑皮
這個好，Morgan 日誌也加進去，方便除錯
→ 决策：demo.js 全域 mock + Morgan HTTP 日誌
v3.0 — 亮/暗版主題 + 追蹤系統 + Hash 路由
黑皮
想要能做亮暗版切換，這樣看起來更專業
Hermes
用 CSS 變數 + `data-theme` 屬性在 html 元素上，Js 只要改 html 的 data-theme 值就能切換，不需要重整頁面。主題樣式全部集中在 style.css。
黑皮
好。另外想要有個人頁，可以看到每個人發過什麼文，也能追蹤別人
Hermes
新增一個 `follows` 資料表（follower / following），用 Hash SPA 路由（`/#/profile/:username`）實作，URL 可以直接分享個人頁，不需要後端支援。
黑皮
OK，就這樣做
→ 决策：CSS 變數亮暗版 + follows 資料表 + Hash SPA 路由
